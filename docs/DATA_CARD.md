# Данные и методика

Источник — `generate()` в `data.py`, не выгрузка организации. Идентификаторы `E0000` и номера дней вымышлены. Единица наблюдения — сотрудник-день. Даты календаря, голоса, тексты разговоров, ФИО и идентификаторы клиентов не используются.

## Признаки

- `tickets_printed`: количество напечатанных талонов.
- `served_customers`: количество обслуженных клиентов.
- `reprints`: повторные печати.
- `cancelled_tickets`: отменённые талоны.
- `median_print_gap_seconds`: медианный промежуток между печатями.
- `short_gap_share`: доля коротких интервалов.
- `after_hours_share`: доля событий вне рабочего времени.
- `repeat_customer_share`: доля повторных клиентов.
- `same_terminal_reuse_share`: доля повторного использования того же терминала.
- `unique_customers`: количество уникальных клиентов.
- `staff_session_minutes`: длительность рабочей сессии.
- `manual_override_count`: количество ручных исключений.

Это демонстрационная схема агрегатов. В настоящем проекте определения, допустимость сбора, полноту логов, временные окна и правила агрегации нужно согласовать с владельцем системы. Здесь нет SQL-коннектора к банку или извлечения событий из реального терминала.

## Нормальная активность и аномалии

Нормальная активность зависит от условной нагрузки сотрудника, недельного цикла и случайного шума. Четыре процента записей первоначально генерируются с повышенной легитимной нагрузкой; количество клиентов и талонов растёт согласованно. Высокая нагрузка сама по себе не получает метку нарушения.

Только в последнем периоде изменяются 5% записей: массовая печать, повторное использование, внеурочная активность и менее выраженное несоответствие счётчиков. Метки `label` и `scenario` известны из генератора. Они не являются реальной разметкой нарушений и не входят в матрицу признаков.

## Разделение и порог

Сначала данные делятся по номеру дня. Обучение и калибровка полностью нормальные по конструкции. Это удобное допущение для учебного one-class / novelty detection; реальная нормальная выборка может содержать неизвестные нарушения.

`StandardScaler`, PCA, Isolation Forest и автоэнкодер обучаются только на днях 0–59. Для автоэнкодера целевым вектором служит тот же преобразованный вход `X`, а не fraud-метка. Внутренняя случайная early-stopping выборка отключена. Остановка определяется тренировочной ошибкой и фиксированным пределом эпох.

Порог для каждой модели выбирается независимо на нормальных днях 60–89. Используется квантиль 0.99 с методом `higher`; флаг формируется при строго большем значении. При равных значениях фактическая доля тревог может быть ниже 1%.

Тест — дни 90–119. Порог, признаки и архитектуру по тестовым меткам не подбирают. В разных периодах присутствуют те же сотрудники, поэтому эксперимент не измеряет перенос на ранее неизвестных сотрудников, банки или терминалы.

## Интерпретация

`average_precision` — average precision, а не площадь трапеций под PR-кривой. Precision зависит от искусственно выбранной доли аномалий 5%. В реальной редкой популяции значение может заметно измениться.

Три признака с максимальной ошибкой восстановления в `review_queue.csv` показывают, где реконструкция отличается от входа. Это не причинное объяснение и не доказательство нарушения. В файле метки и сценарии включены для проверки учебного эксперимента; `score` работает без них.

Seed фиксирует генератор и начальные параметры. Численные библиотеки и платформы могут дать небольшие отличия; эталонное окружение сохранено в `requirements-lock.txt`, версии запуска — в `metrics.json`. Тестовое число сотрудников, доля аномалий и ограничения генератора — часть постановки, а не сведения о конкретном банке.
